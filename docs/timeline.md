# Investigation history

All work described here took place on 23 October 2026 unless another date is explicitly identified as historical device data. This is a reconstructed research chronology, not a verbatim conversation or shell-history dump.

| Stage | Work and result | Limits or correction |
| --- | --- | --- |
| Scope | Began with a hardware-research handoff and a Spotify Connect quality question. Owner redirected the objective to firmware access and modification feasibility. | The bitrate investigation was dropped. No bitrate fix was implemented. |
| Host setup | The actual execution host was macOS. `lsusb` was unavailable. | Linux commands in the initial handoff were not evidence about the current Mac. IORegistry was used instead. |
| USB | Confirmed the connected MEGABLAST, VID/PID `046d:0a6a`, one HID interface, vendor usage page, and 64-byte reports. | `bcdDevice=0x0403` was not treated as the complete speaker version. No USB output commands were sent. |
| LAN | Bonjour found Spotify Connect on port 9595. The owner retrieved ZeroConf metadata successfully. | The agent's requests failed despite the owner's successful equivalent request. VPN routing/local-network blocking was investigated; failed requests did not prove closed ports. |
| Firmware identity | Owner read 3.4.216 in the iPhone companion app. | Initially owner-reported; subsequently confirmed directly over BLE. |
| Manufacturer artifacts | Extracted download links from historical FAQ PDFs; acquired original diagnostic DMG and MSI. | Old Update Assistant HEAD requests returned 404. Internet Archive availability API returned 429, leaving archive recovery unresolved. |
| Desktop extraction | Used 7-Zip to inspect DMG, MSI/CAB, and appended Windows ZIP layers. Found NW.js app, node-hid, and compiled V8 caches. | No obvious firmware payload in the inspected inventory. A filename ending `.bin` was not assumed to be speaker firmware. |
| Desktop execution boundary | Extracted Mac app and launcher failed code-signature verification. A native DMG mount displayed an EULA and canceled. | No agreement accepted, app launched, signature bypassed, or original app re-signed. |
| Static desktop analysis | Identified NW.js 0.31.1, V8 6.7.288.44, getter/filesystem/reset/boot-mode strings. REA analyzed selected manifest/HTML sources. | String names did not recover numeric USB packets. REA's selected analysis did not decode the V8 caches. |
| Decoder compatibility | Compared ghidra_nodejs, Theia, and View8 version assumptions. | No compatible decoder or validated adaptation established. Changing cache magic alone would be insufficient. |
| Android acquisition | Obtained companion APK 2.2.121 through the mirror's normal browser download after consent rejection. Hash and embedded certificate fingerprint matched mirror metadata. | Mirror consistency is not an independent trust anchor. APK was never installed or executed. |
| Java correction | `/usr/bin/java` could not find a JVM, but the existing Homebrew `openjdk@25` worked through its direct path. | An unnecessarily downloaded portable JRE remained unused. The investigation did not install global Java or change REA configuration. |
| Android analysis | Official JADX 1.5.6 decoded 6,597 classes with 16 reported errors. Relevant protocol methods had complete bodies. | REA's Android provider was unconfigured, so standalone JADX was used. The full app was not perfectly recovered. |
| Centurion definitions | Recovered root feature lookup, firmware getter, numbered-file read, BLE/CPL framing, authorization handshake, OTA host/status, and validation vocabulary. | APK contains no USB transport. No firmware-image file ID, raw-flash reader, or payload URL established. |
| OTA endpoints | Downloaded service-locator XML; historical PHP endpoint returned 403; production root and `/ue/speaker` returned `{}`. | No device identifier or account credentials sent. XML consumer located in this APK concerned geolocation. |
| Bluetooth availability | Sandboxed process reported unsupported Bluetooth. Approved execution outside the tool sandbox could discover one matching speaker. | This was a process access restriction, not proof of absent hardware. |
| Notification compatibility | GATT connection succeeded; normal subscription failed with ATT error 10 because CCCDs were absent. The local Bleak callback still received replies. | This relies on observed Bleak 3.0.2 behavior. The app uses Android COMPAT notification mode. |
| Initial getter | Root lookup returned `NOT_AUTHORIZED`, error 14. | No guessed authorization packet was sent. Owner separately approved the normal handshake and diagnostic reads. |
| Authorization trials | Tried acknowledged and app-style unacknowledged writes, physical button confirmation, and closing the phone app. Several attempts timed out; one early success notification was followed by denial. | Another phone connection was a hypothesis, not a proven cause. An unacknowledged command trial got no reply; this did not prove exactly where it was dropped. |
| Authorization success | A timely button confirmation produced status 0 after 7.144 seconds in one captured session. After the app's 250 ms delay, feature lookup and firmware getter succeeded. | Later connections with the same client ID worked without another press. Power-cycle persistence was not tested. |
| Live getters | Firmware 3.4.216; DeviceInfo index 2/version 2; OTA index 17/version 3; status 5, parameter `0x01000000`, automatic install mode. | No OTA check or install initiated. Parameter interpretation remains status-dependent. |
| Log SIZE discrepancy | Filesystem index 5/version 3 returned an empty SIZE acknowledgement. A later notification carried event 3 with size and CRC. | The Android synchronous parser did not describe this format. The probe was adapted to the observed event. |
| Short log sample | Opened log 66 for reading, read 64 bytes, and closed it. | An exploratory collector timed out while waiting for more notifications after the successful sample; the timeout did not negate the read. |
| Long-read failure | A large read triggered a Bleak callback `InvalidStateError` and CPL ordering failure. | CoreBluetooth confused a two-byte notification with a pending read response. A notification discriminator fixed the distinction. |
| Full log | Acquired 193,321 bytes and closed log 66. Standard CRC `69a38792` matched the bitwise inverse of device value `965c786d`. | Raw log contains authentication-related and identifying content and remains excluded. |
| Log inspection | Found older 3.2.200/3.3.213/3.4.216 crash records and a successful 3.3.213 → 3.4.216 update logged on 11 October 2020. | No manufacturer firmware URL/domain found. Recorded date is this unit's historical data, not a global release date. |
| Metadata inventory | Read all 24 advertised feature entries and hardware revision 1. | Empty Root GET_PROTOCOL_VERSION returned error 3 (`INVALID_SIZE`); no guessed payload retry. No raw-flash feature explicitly identified. |
| Legacy runtime detour | Downloaded official macOS x64 NW.js SDK 0.31.1. Wrote a fake-HID harness and deny-default sandbox fixtures. | Original diagnostic app, `gui.bin`, `njch.bin`, and `njcc.bin` were not executed. |
| Sandbox preflight | Authored Node fixture passed read/write, private-read denial, outside-write denial, child-exec denial, and loopback-denial checks. | The separately adapted NW profile did not receive equivalent successful end-to-end validation. |
| NW startup failures | Iteratively diagnosed Rosetta/system-library reads, random source, helper startup, resource extension, and private socket failures. Last attempt exited 21 with ProcessSingleton failure. | The authored page never produced its result. No vendor cache loaded and no USB bytes recovered. This detour was stopped after the owner challenged its cost. |
| Archive | Collected the useful results, failed attempts, source provenance, and test code in this repository. | Sanitization and archive verification are separate from the historical live tests. |

The defensible result is diagnostic access with a confirmed firmware version and a verified log acquisition. A full firmware image and evidence of safe modification remain missing.
